# Инструкции для AI-агентов

Перед изменениями прочитайте [CONTRIBUTING.md](CONTRIBUTING.md),
[требования](docs/specification.md) и [текущее состояние](docs/implementation-plan.md).
Инструкции пользователя имеют приоритет.

- Изменяйте только этот репозиторий. Окружение, кеши и временные файлы размещайте
  в `.local/`; внешние исходники подключайте только для чтения.
- Работайте в `main`, если пользователь не указал другую ветку. Каждый завершённый
  связный блок после проверок оформляйте отдельным Conventional Commit на английском
  без `Co-Authored-By`. Не включайте чужие изменения. Push выполняйте только по запросу.
- Запрошенные изменения и локальные коммиты разрешены. Неопределённые бизнес-правила
  уточняйте до зависимой реализации; независимую работу продолжайте.
- Minishop управляет подписками, тегами и сквадами. Используйте его сервисы и DAL
  через `integration/`. Не создавайте прямой клиент Remnawave, не правьте ядро,
  не подменяйте глобальные методы и не записывайте таблицы ядра сырым SQL.
- Совместимость проверяйте на стабильном Minishop из `dev/minishop.json`.
  Плагин не проверяет версию Remnawave. Смена базы требует повторной проверки.
- Дата контракта абсолютная. Общая сверка раз в 6 часов обходит нынешних участников
  порциями, не затрагивает бывших и не создаёт персональных расписаний.
- Выход и исключение выдают один новый стандартный триал на операцию. Если триал
  выключен или его срок неположительный, доступ отключается с возможностью личной покупки.
  Истечение сохраняет членство и само по себе триал не выдаёт.
- Вступление требует отключённого автопродления и завершённых/отменённых личных
  платежей. Плагин проверяет это через Minishop и ничего не отменяет самостоятельно.
  После исключения разрешено новое вступление по действующему приглашению.
- Проверяйте пользователя, роль и принадлежность контракту на сервере для каждого
  действия. Управляющий не получает глобальных прав администратора.
- Лимиты приглашений, резервирование и повторы должны выдерживать конкуренцию.
  Защита кодов использует Minishop и политику плагина, без отдельного IP-лимита.
- Используйте данные и кеш Minishop, отсутствие кеша обновляйте штатными сервисами.
  Не подменяйте недоступное значение нулём. Персонального запрета покупок в SDK нет.
- Таблицы имеют префикс `ext_minishop_corp_`, миграции — `minishop-corp.`.
  Применённые миграции не изменяйте. Удаление аккаунта не должно блокироваться
  корпоративными связями, даже при выключенном плагине; триал при удалении не выдаётся.
- Сохраняйте HTTP-конверт `{"ok": ...}`, Plugin API и frontend host API.
  Типизируйте Python и TypeScript; не скрывайте ошибки широкими `Any`/`any`.
- Все видимые строки и ошибки локализуйте в RU/EN. Используйте зарегистрированные
  страницы и слоты, собственный DOM и стили в области плагина.
- Генерируйте bundles, ZIP, manifest, хеши и подписи штатными скриптами.
  Секреты, реальные приглашения и данные клиентов не включайте в Git и пакет.
- Actions отвечает за сборку подписанного пакета с постоянным ключом из Secret.
  Основная ветка публикует
  индекс и ZIP одним коммитом. Проверки и стенды запускайте локально; Minishop в Actions не нужен.

Выберите проверки по матрице CONTRIBUTING.md. Обновите текущее состояние, не отмечая
незавершённое выполненным. В отчёте укажите результат, проверки, ограничения и коммиты.
