# Переход на стабильный Minishop 3.8.1

Решение владельца от 9 октября 2026 года: разработка, тесты и установочный пакет
ориентируются на стабильный релиз Minishop 3.8.1. Работа ведётся в ветке
`vibe/minishop-3-8-1`; это обновление базы совместимости S02/S10.

## Основание и область изменений

В официальном репозитории тег `v3.8.1` указывает на
`bc3379812b370ed4420b97338fc24fce5c87f1a6`. Значение проверено через `git ls-remote`
и совпадает с сообщённой рабочей сборкой `v3.8.1+gbc3379812b370ed4420b97338fc24`.
Предыдущая база `507563b06a564a26ecb10cd4c249dcd588cbff05` отличается от этого тега
только `CHANGELOG.md`; исходники, зависимости и Plugin API совпадают.

В [dev/minishop.json](../dev/minishop.json) закрепляются релизный тег и полный commit.
По умолчанию локальные команды читают `.local/minishop` внутри этого репозитория.
Явный `MINISHOP_SOURCE` допускается только для чистого checkout той же ревизии.
Соседние исходники и их Git-состояние остаются доступными только для чтения.

Пакет 0.1.1 получает новый `core_revision`; подписанный пакет 0.1.0 сохраняется
отдельным предыдущим кандидатом. Генератор, ключ издателя и формат подписи прежние.
Сервисы и модели плагина меняются только при обнаруженной несовместимости.
Версию Remnawave плагин не проверяет; этой интеграцией управляет Minishop.
GitHub Actions по-прежнему только собирает подписанный артефакт без Minishop/kiro-wheel.

## План и критерии приёмки

1. Закрепить `v3.8.1` и его commit, подготовить отдельный checkout и проверку ревизии
   перед локальной настройкой, тестами, стендом и упаковкой. Неверная ревизия должна
   отклоняться до запуска зависимых действий.
2. Выполнить Python/TypeScript/DOM, интеграционные сценарии на PostgreSQL,
   native smoke и браузерные сценарии, включая полную оболочку релиза.
3. Собрать подписанный пакет 0.1.1 и проверить его установку, обновление,
   перезапуски и сохранение данных на релизном ядре. Проверить точный `core_revision`
   и воспроизводимость архива; сохранить прежний ключ издателя.
4. Обновить инструкции и отчёт фактическими результатами. Зафиксировать связный
   блок отдельным коммитом после проверок. Push и установка на рабочий бот не выполняются.

## Реализация и проверка 9 октября 2026 года

Релизный checkout подготовлен в `.local/minishop`; тег и HEAD совпадают с pin.
`scripts/check-minishop.sh` проверяет эту ревизию и чистоту checkout до запуска
зависимых команд. Проверено, что десять точек запуска отклоняют прежнюю dev-ревизию;
для отсутствующего checkout выводится инструкция подготовки. `GIT_OPTIONAL_LOCKS=0`
предотвращает необязательные изменения Git index при чтении соседних репозиториев.

Backend и locales ядра подключаются к контейнерам только для чтения. Отдельный файл
с commit проверенного checkout подключается как `/minishop/.build-commit`.
Smoke и сценарий установки проверяют, что native установщик видит точную ревизию:
приёмка пакета проходит с действующей проверкой `core_revision`.
Логика адаптера, схемы данных и зависимости не изменились.

в рамках этого перехода не выполнялись.
