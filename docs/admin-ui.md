# Админка корпоративных контрактов: S08

Раздел «Корпоративные контракты» зарегистрирован через административное UI-расширение
Minishop. Он использует API плагина, штатную cookie-сессию и `X-CSRF-Token` из cookie
Minishop. Управляющий организации по-прежнему не получает доступ к этому разделу.
Его пользовательский кабинет описан в [S09](customer-ui.md).

## Контракты и условия

Список показывает название, тариф, точный срок в UTC, состояние и число нынешних
участников. Порция — 25 контрактов; «Показать ещё» продолжает обход по UUID.
Кнопка «Создать контракт» открывает форму:

- название организации;
- period-тариф, включая скрытые; код доступа скрытого тарифа не передаётся в UI;
- точные дата и время окончания **в UTC**, включая миллисекунды, если они заданы;
- UUID внешнего сквада с кнопкой проверки и показом его имени;
- существующий аккаунт управляющего: недавние аккаунты или точный поиск по внутреннему
  ID / username. Заблокированные аккаунты не предлагаются.

Minishop закреплённой ревизии предоставляет получение внешнего сквада по UUID,
но не список внешних сквадов. Форма использует этот проверенный путь. Проверка
выбранных ссылок при сохранении остаётся на сервере. Детали — в
[API контрактов](contracts-api.md).

Изменение существующих условий требует подтверждения с названием, тарифом и сроком.
Сообщение о сохранении относится к условиям: применение к участникам отслеживается
на отдельной вкладке. Конфликт версии сохраняет введённые поля и предлагает загрузить
сохранённые условия. Эта загрузка, как и выход из формы, предупреждает о потере правок.
Обновление справочников, переход между вкладками и обновление языка host не стирают поля.

После потери ответа UI удерживает неизменный запрос и его UUID, блокирует другие
изменения и предлагает повторить именно его. Повтор создания не заводит второй контракт.
Для потерянного PUT ответ проверяется повторным чтением: совпадение целевых условий
считается подтверждением; чужие новые условия не перезаписываются автоматически.
Идентификаторы запроса создаются через Web Crypto, в том числе в локальном HTTP preview.

## Приглашения

Доступны одноразовый код и постоянный код с положительным лимитом успешных вступлений.
История показывает тип, дату, использованные/зарезервированные активации и состояние.
Отзыв и смена постоянного кода требуют подтверждения; смена сохраняет лимит, а новый
код имеет собственный счётчик. Уже принятые вступления и участники сохраняются.
При истёкшем контракте выпуск и смена отключены, просмотр и отзыв доступны.

Код и ссылка показываются только после выпуска/смены. Их можно скопировать или скрыть.
Они хранятся в памяти открытого интерфейса, не в localStorage, URL страницы или логах.
Если адрес приглашения не настроен, предлагается передать код. После потери ответа
повтор с тем же UUID не создаёт второй код; UI объясняет, что секрет повторно не выдаётся
и требуется отзыв одноразового либо смена постоянного приглашения. При неопределённом
результате смены прежний код скрывается: сервер уже мог его отозвать.
Переход между вкладками сохраняет показанный код, закрытие раздела удаляет его из памяти.

## Участники

Карточки показывают разрешённые поля профиля, Telegram-ссылку при привязанном Telegram,
аватар, трафик за текущий период учёта Minishop и число устройств вместе с лимитами.
Порция — 25 участников; трафик не является отдельным счётчиком с момента вступления.
Значения «нет данных», сохранённые и устаревшие данные различаются; ноль не используется
вместо отсутствующего значения. Нулевой лимит обозначает безлимит. Статистика и аватары
обновляются через сервисы Minishop; загрузки аватаров ограничены четырьмя одновременно.
Профиль вставляется текстом, изображения ограничены полученными растровыми data URL.

Исключение показывает имя участника и последствия: аккаунт сохранится, будет выдан
новый стандартный триал, а при недоступном триале корпоративный доступ завершится
с возможностью личной покупки. После принятия запроса UI показывает ожидание операции.
Он не выдаёт принятие запроса за подтверждённое снятие доступа. Пока есть вступающие
или выходящие участники, первая страница открытой вкладки обновляется каждые 10 секунд; доступна и
ручная кнопка обновления. Права на действие по-прежнему проверяет сервер.

## Применение условий

Вкладка показывает текущую версию, подтверждённых участников, ожидание постановки,
вступление/выход, очередь, выполнение и повторы после ошибок. Видны время следующей
общей сверки, факт завершения обхода и незавершённые операции с аккаунтом, ошибкой,
числом попыток и временем следующей попытки. Сам обход не означает, что доступ уже
изменён у всех участников.

Первая страница открытой вкладки обновляется каждые 10 секунд. После загрузки
дополнительных страниц автоматическое обновление приостанавливается, чтобы не
сбрасывать изучаемый список; ручное обновление возвращает первую страницу.
Автообновление приостанавливается и на время подтверждения действия.
Выход из раздела отменяет запросы, таймеры и подтверждения. Чужой DOM не меняется.

## Проверки и ограничения

DOM-тесты — [admin.test.mjs](../tests/frontend/admin.test.mjs): повторы после потери
ответа, конфликт версии, подтверждения, локализация, сохранение полей, пагинация,
истечение, отсутствие Telegram/данных, безопасный текст профиля и очистка при размонтировании.
Браузерные сценарии — [admin.mjs](../tests/browser/admin.mjs): создание/изменение,
одноразовые/постоянные коды, отзыв/смена, исключение, ошибки операций, клавиатурные
вкладки и адаптивность в RU/EN, светлой/тёмной темах, на ширинах 375/1280 px.

Browser-прогон загружает подписанные bundles из настоящего Minishop. Начальный просмотр
списка и проверка авторизации работают с настоящим backend. Для изменяющих сценариев
браузер подставляет синтетические ответы API; отдельно интеграционные тесты проверяют
реальные сервисы/DAL Minishop и PostgreSQL с HTTP-двойниками панели и Telegram.
Изолированный preview остаётся прокси только для чтения, не проксирует изменяющие запросы.
Это проверка на закреплённой версии, а не применение к рабочему боту.

Ограничение C-01 из [совместимости](minishop-compatibility.md) сохраняется.
В 0.1.2 C-02 пересмотрено: редактор показывает удалённого управляющего, допускает
изменение условий существующего контракта без него и выбор замены. При создании
нового контракта управляющий по-прежнему обязателен.
Открытие ссылок и кабинет участника/управляющего реализованы в [S09](customer-ui.md).
