# Админка корпоративных подписок: S08

Раздел «Корпоративные подписки» зарегистрирован через административное UI-расширение
Minishop. Он использует API плагина, штатную cookie-сессию и `X-CSRF-Token` из cookie
Minishop. Управляющий организации по-прежнему не получает доступ к этому разделу.
Его пользовательский кабинет описан в [S09](customer-ui.md).
Ошибка API и пустой результат поиска в админке показывают код диагностики для
сопоставления с backend; порядок получения журналов описан в [инструкции отладки](logging.md).

## Контракты и условия

Список показывает название, тариф, точный срок в UTC, состояние и число нынешних
участников. Порция — 25 контрактов; «Показать ещё» продолжает обход по UUID.
Кнопка «Создать подписку» открывает форму:

- название подписки;
- period-тариф, включая скрытые; код доступа скрытого тарифа не передаётся в UI;
- календарная дата, по умолчанию сегодня в часовом поясе браузера администратора;
  доступ действует до начала следующего дня (выбранный день включён полностью);
- кнопки прибавления дня, недели, 1/3/6 календарных месяцев и года к выбранной дате;
- необязательный UUID внешнего сквада с кнопкой проверки и показом его имени;
- одно необязательное поле управляющего: публичный ID Minishop `ms_…`, Telegram ID,
  @username или email, поиск по кнопке
  и явное подтверждение найденного аккаунта. Каталог аккаунтов не загружается;
  заблокированные аккаунты не предлагаются.

Minishop закреплённой ревизии предоставляет получение внешнего сквада по UUID,
но не список внешних сквадов. Форма использует этот проверенный путь. Проверка
выбранных ссылок при сохранении остаётся на сервере. Детали — в
[API контрактов](contracts-api.md).
Пустое поле означает отсутствие корпоративного переопределения; сервер не выполняет
поиск сквада. При снятии прежнего сквада плагин через Minishop возвращает штатное
поведение, в том числе явно убирает старый сквад, если глобальный сквад не задан.

Изменение существующих условий требует подтверждения с названием, тарифом и сроком.
Сообщение о сохранении относится к условиям: применение к участникам отслеживается
на отдельной вкладке. Конфликт версии сохраняет введённые поля и предлагает загрузить
сохранённые условия. Эта загрузка, как и выход из формы, предупреждает о потере правок.
В новой форме нет кнопки «Обновить»; при ошибке начальной загрузки доступен повтор.
Переход между вкладками и обновление языка host не стирают поля.
Часовой пояс явно указан у даты. Календарные месяцы ограничиваются последним днём
целевого месяца; переходы летнего времени учитываются браузером. Старый точный срок
сохраняется при изменении других полей, пока дата явно не изменена.

После потери ответа UI удерживает неизменный запрос и его UUID, блокирует другие
изменения и предлагает повторить именно его. Повтор создания не заводит второй контракт.
Для потерянного PUT ответ проверяется повторным чтением: совпадение целевых условий
считается подтверждением; чужие новые условия не перезаписываются автоматически.
Идентификаторы запроса создаются через Web Crypto, в том числе в локальном HTTP preview.

## Приглашения

Доступны одноразовый код и постоянный код с положительным лимитом успешных вступлений.
История показывает тип, дату, использованные/зарезервированные активации и состояние.
Отзыв и смена постоянного кода требуют подтверждения; смена сохраняет лимит, а новый
код имеет собственный счётчик. Уже принятые вступления и участники сохраняются.
При истёкшем контракте выпуск и смена отключены, просмотр и отзыв доступны.

С 0.1.6 «Удалить код» полностью удаляет приглашение после подтверждения. Кнопка
недоступна при занятом резерве, сервер также проверяет незавершённое вступление.
Участники и их подписки сохраняются; завершённые операции доступны для безопасных повторов.

Код и ссылка находятся в каждой записи списка, доступны повторно после открытия
раздела и могут быть скопированы. Кнопки «Скрыть код» нет. Сервер сохраняет новые коды
в собственных таблицах, но не в логах/аудите. UI не сохраняет их в browser storage
или URL страницы. Если адрес приглашения не настроен, предлагается передать код.
После потери ответа повтор с тем же UUID возвращает уже выпущенный код. При неизвестном
результате смены список остаётся видимым с предупреждением; действия заблокированы
до повтора исходного запроса. После него список отражает отзыв старого кода и новый.
Коды прежних версий сохранились только как хеши: они работают, но вместо текста видна
подсказка выпустить новый одноразовый код либо сменить постоянный. Автоотзыва нет.

## Участники

Карточки показывают аватар, имя/никнейм, публичный ID `ms_…` по образцу штатной админки,
Telegram-ссылку при привязанном Telegram, трафик за текущий период учёта Minishop
и число устройств вместе с лимитами. Внутренний числовой ID не выводится вместо `ms_…`.
Порция — 25 участников; трафик не является отдельным счётчиком с момента вступления.
Значения «нет данных», сохранённые и устаревшие данные различаются; ноль не используется
вместо отсутствующего значения. Нулевой лимит обозначает безлимит. Статистика и аватары
обновляются через сервисы Minishop; загрузки аватаров ограничены четырьмя одновременно.
Профиль вставляется текстом, изображения ограничены полученными растровыми data URL.
Состояние данных вынесено в подсказку, повторяющихся приписок под показателями нет.
Аватары загружаются автоматически без кнопки «Обновить аватары».

«Назначить управляющим» доступно активному участнику только в глобальной админке.
После подтверждения роль переходит этому аккаунту, прежний управляющий теряет доступ.
Черновик условий при его наличии требует явного отказа перед назначением;
тариф и срок сервер не меняет. Глобальные права Minishop не выдаются.

В заголовке сохранённой подписки есть «Удалить подписку». Подтверждение предупреждает
об удалении её кодов и истории плагина. Если остались участники, операции или резервы,
сервер отклоняет удаление с объяснением. После успешного удаления открывается список,
черновик этой подписки очищается. Аккаунты и платежи Minishop сохраняются.

Исключение показывает имя участника и последствия: аккаунт сохранится, будет выдан
новый стандартный триал, а при недоступном триале корпоративный доступ завершится
с возможностью личной покупки. После принятия запроса UI показывает ожидание операции.
Он не выдаёт принятие запроса за подтверждённое снятие доступа. Пока есть вступающие
или выходящие участники, первая страница открытой вкладки обновляется каждые 10 секунд; доступна и
ручная кнопка обновления. Права на действие по-прежнему проверяет сервер.

## Применение условий

Вкладка показывает текущую версию, подтверждённых участников, ожидание постановки,
вступление/выход, очередь, выполнение и повторы после ошибок. Видны время следующей
общей сверки, факт завершения обхода и незавершённые операции с аккаунтом, ошибкой,
числом попыток и временем следующей попытки. Сам обход не означает, что доступ уже
изменён у всех участников.

Первая страница открытой вкладки обновляется каждые 10 секунд. После загрузки
дополнительных страниц автоматическое обновление приостанавливается, чтобы не
сбрасывать изучаемый список; ручное обновление возвращает первую страницу.
Автообновление приостанавливается и на время подтверждения действия.
Выход из раздела отменяет запросы, таймеры и подтверждения. Чужой DOM не меняется.

## Сохранение формы при возврате

Minishop при возврате на вкладку обновляет `/me?fresh=1`, а при переходах между
разделами пересоздаёт UI плагина. Форма и выбранная внутренняя вкладка сохраняются
в `sessionStorage` текущей вкладки браузера. Восстановление происходит только после
серверной проверки глобальных прав и текущего `actor_user_id`; другой аккаунт не
получает прежний черновик. Ошибка 401/403, подтверждённый отказ от правок и сохранение
очищают черновик. Запись старше суток не восстанавливается. При запрещённом браузером
хранилище остаётся память страницы: она переживает пересоздание UI, но не перезагрузку.

Сохраняются только поля редактора, исходная версия и неизменный запрос при неопределённом
результате сохранения. Коды приглашений, профили участников, токены и ответы сторонних
сервисов туда не записываются. После перезагрузки неопределённый запрос предлагается
повторить явно; автоматического POST/PUT нет. Сохранённая версия не заменяется свежей
без решения администратора, поэтому чужие изменения по-прежнему дают конфликт.

Полная браузерная матрица использует отдельный `dev/core-ui.yaml`: восемь аккаунтов
с одного IP многократно загружают все API оболочки, поэтому только на этом локальном
стенде повышен `WEBAPP_RATE_LIMIT_MAX_REQUESTS`. Настройки рабочего Minishop и защита
приглашений Q-01 плагином не меняются.

## Проверки и ограничения

DOM-тесты — [admin.test.mjs](../tests/frontend/admin.test.mjs): повторы после потери
ответа, конфликт версии, подтверждения, локализация, сохранение полей, пагинация,
истечение, отсутствие Telegram/данных, безопасный текст профиля и очистка при размонтировании.
Браузерные сценарии — [admin.mjs](../tests/browser/admin.mjs): создание/изменение,
одноразовые/постоянные коды, отзыв/смена, исключение, ошибки операций, клавиатурные
вкладки и адаптивность в RU/EN, светлой/тёмной темах, на ширинах 375/1280 px.

Browser-прогон загружает подписанные bundles из настоящего Minishop. Начальный просмотр
списка и проверка авторизации работают с настоящим backend. Для изменяющих сценариев
браузер подставляет синтетические ответы API; отдельно интеграционные тесты проверяют
реальные сервисы/DAL Minishop и PostgreSQL с HTTP-двойниками панели и Telegram.
Изолированный preview остаётся прокси только для чтения, не проксирует изменяющие запросы.
Это проверка на закреплённой версии, а не применение к рабочему боту.

Ограничение C-01 из [совместимости](minishop-compatibility.md) сохраняется.
В 0.1.2 C-02 пересмотрено: редактор показывает удалённого управляющего, допускает
изменение условий существующего контракта без него и выбор замены. При создании
нового контракта управляющий с 0.1.4 необязателен. Пустое поле оставляет управление
глобальному администратору; кнопка «Не назначать управляющего» снимает выбор.
Изменение действующего контракта применяется только после сохранения и подтверждения.
Открытие ссылок и кабинет участника/управляющего реализованы в [S09](customer-ui.md).
