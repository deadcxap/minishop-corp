# Проверка совместимости с Minishop 3.8.2

Дата проверки: **14 октября 2026 года**. Проверен исходный код minishop-corp
**0.1.9** на стабильном [теге Minishop v3.8.2](https://gitlab.com/3252a8/remnawave-minishop/-/tags/v3.8.2),
commit `04b0ca5e210a33209bbf15485003865ee29304bc`.

**Полная совместимость не подтверждена: воспроизведены две ошибки в новых
сценариях ядра.** Принятой базой остаётся Minishop 3.8.1 в
[dev/minishop.json](../dev/minishop.json). Рабочий код плагина не изменён.

## 1. Новые автоплатежи не учитываются перед вступлением

В 3.8.2 появились `ProviderMandate` и провайдеры `cryptomus_subscription`,
`cispay_subscription_card`, `cispay_subscription_sbp`. Штатный DAL считает
состояния `pending`, `active`, `paused`, `past_due` действующими.

[Проверка платежей плагина](../backend/minishop_corp/integration/billing.py)
учитывает флаг подписки, Wata, RollyPay, Tribute, открытые циклы и незавершённые
платежи, но не новую таблицу мандатов. Если локальный `auto_renew_enabled=False`,
нет открытого цикла и исходный платёж уже завершён, действующий мандат не мешает
вступлению. Это позволяет принять корпоративные условия при продолжающемся
внешнем автоплатеже; последующий платёж может снова изменить личную подписку.

В PostgreSQL воспроизведены все **12 сочетаний** трёх провайдеров и четырёх
действующих состояний. Ожидаемый `renewal_policy_required` не возвращается.
Исправление должно проверять мандаты через Minishop и требовать штатного
отключения пользователем, сохраняя запрет автоматической отмены платежей плагином.

## 2. Выход расходует отложенный приветственный бонус без его дней

При `REFERRAL_WELCOME_BONUS_ADDS_TO_TRIAL=True` штатная активация триала в 3.8.2
прибавляет ещё не полученный приветственный бонус и записывает
`referral_welcome_bonus_claimed_at`. Аргумент `emit_event=False` подавляет события,
но не начисление и отметку получения.

[Адаптер выхода](../backend/minishop_corp/integration/access.py) затем возвращает
срок к сохранённому стандартному окну триала. В проверке стандартный триал —
3 дня, бонус — 7 дней: итоговый доступ составляет 3 дня, а бонус уже считается
полученным. Это побочный реферальный эффект корпоративного выхода/исключения,
противоречащий существующим требованиям. При выключенной настройке контрольный
сценарий проходит. По умолчанию эта настройка Minishop выключена.

Нужен путь выдачи стандартного триала без расходования отложенного реферального
бонуса, через штатные сервисы/DAL и без глобальных подмен ядра.

## Проверки

Для проверки временно использовались pin на 3.8.2 и Python lock, пересобранный
`scripts/lock-python.sh` с ограничениями новой версии ядра. После проверки pin,
lock и локальное окружение возвращены на принятую базу 3.8.1.

| Проверка на 3.8.2 | Результат |
| --- | --- |
| Ruff и строгий mypy | Успешно |
| Unit-тесты | 38 прошли после актуализации ожидания установщика |
| TypeScript, ESM, wheel с RU/EN | Успешно |
| DOM | 54 прошли |
| Существующий интеграционный набор PostgreSQL | 324 прошли после актуализации импортов тестов |
| Новые проверки политик 3.8.2 | 13 упали, 1 прошла; воспроизводят две описанные ошибки |
| Штатные backend/worker, авторизация, API, подписанные ресурсы | Успешно |
| Chromium preview | 43 сценария прошли |
| Chromium в полной оболочке 3.8.2 | 8 сценариев прошли |
| Установка и обновление подписанного пакета | Успешно: чистая установка, обновление, повторы, выключение/включение, сохранность данных и десяти миграций |

В тестах удаления импорт заменён на совместимый экспорт
`db.dal.user_dal.delete_user_and_relations`: в 3.8.2 реализация перенесена из
`user_merge_dal` в `user_delete_dal`. Рабочий плагин от старого импорта не зависел.
Установщик 3.8.2 трактует версии возможностей как минимальные, поэтому проверка
отказа теперь использует отсутствующую возможность или версию 0. Тесты больше
не требуют ошибочного отказа при версии 2 вместо требуемой 1.

Новые [регрессионные сценарии](../tests/integration/test_minishop_382_compatibility.py)
включаются при наличии `ProviderMandate`. На 3.8.1 они пропускаются из-за
отсутствия соответствующего API, на 3.8.2 фиксируют ошибки без `xfail`.

После возврата на 3.8.1 повторно прошёл `scripts/check.sh`, а целевой прогон
изменённых интеграционных модулей дал **41 passed, 14 skipped**. Пропущены только
новые сценарии 3.8.2; это не свидетельство совместимости с новой версией.

Установщик 3.8.2 также принял существующий подписанный ZIP **0.1.8** из индекса
репозитория. Его `integration/billing.py` и `integration/access.py` побайтово
совпадают с 0.1.9, поэтому обе найденные ошибки относятся и к этому архиву.
Успешное принятие пакета не заменяет проверку его поведения.

Логи проверки находятся локально в `.local/compat-3.8.2/`. Проверки использовали
синтетические аккаунты, PostgreSQL и HTTP-двойники панели/Telegram. Рабочие
провайдеры оплаты, реальная панель и рабочий бот не проверялись и не изменялись.

## До принятия новой базы

Исправить обе ошибки, добиться успешного прохождения новых сценариев и повторить
приёмку по [матрице](acceptance.md). До этого 3.8.2 не объявляется полностью
совместимой базой. Новая версия плагина и её публикация этой проверкой не выпускаются.
