# Изменение условий и общая сверка: S06

Плагин регистрирует `minishop-corp.reconciliation` через `WorkerTaskSpec` Minishop.
Это одна общая периодическая сверка всех контрактов: отдельного расписания на каждого
участника нет. Изменение условий контракта запускает применение без ожидания шести часов.
Все изменения доступа выполняются через очередь `minishop-corp.operations` и адаптер
сервисов/DAL Minishop.

## Общий запуск

Таблица `ext_minishop_corp_reconciliation_sweep` содержит единственную строку `id=1`:
номер запуска `run_id`, общий срок `next_run_at`, начало и завершение обхода, курсор
`after_member_id`, токен и срок аренды. Начальное расписание допускает немедленный запуск.
Следующее время назначается на шесть часов после начала текущего запуска.

Несколько процессов worker разделяют эту строку. Один из них забирает порцию через
`FOR UPDATE SKIP LOCKED` и сохраняет двухминутную аренду. Порция содержит не более
100 текущих активных членств из всех контрактов, упорядоченных по UUID. Истёкший
контракт и неактивная подписка остаются в выборке; подписку не фильтруют по активности
Minishop. `pending`, `leaving` и бывшие участники не обрабатываются.

Для каждого участника короткая транзакция проверяет актуальность и сохраняет операцию
`reconcile`. Вместе с ней записывается `scheduled_run_id`: это отметка постановки
в очередь, а не персональный таймер и не подтверждение доступа. Участники, появившиеся
после начала обхода, получат проверку в следующем запуске; само вступление уже применяет
актуальные условия. Порции не удерживают общую транзакцию на время HTTP-запросов.

Занятый аккаунт или контракт пропускается без ожидания. После конца списка курсор
возвращается к пропущенным записям этого же запуска. Ошибка одной транзакции не отменяет
постановку остальных; необработанная запись остаётся без отметки. На пустом проходе
worker делает паузу две секунды, при ошибке самого цикла — пять секунд.

После фиксации порции аренда освобождается. При аварии другой процесс восстанавливает
тот же `run_id` и курсор по истечении аренды. Повтор уже поставленного участника
не создаёт вторую операцию. Старый токен не может дописать операции или завершить обход
после смены владельца. При долгом отключении пропущенные интервалы объединяются
в один актуальный обход, без очереди устаревших шестичасовых запусков.

`completed_at` означает завершение **обхода и постановки операций**. Применение доступа
может ещё выполняться или повторяться после сбоя; его результат показывают отдельные
счётчики и операции.

## Изменение контракта

Новая версия контракта и её снимок сохраняются атомарно существующим API. Расхождение
`memberships.scheduled_version` с версией контракта — устойчивый признак необходимости
применения. Тот же планировщик постоянно выбирает такие записи порциями, независимо
от общего шестичасового срока. В отсутствие работы он проверяет изменения раз в две
секунды. HTTP-ответ сохранения условий не означает, что все подписки уже обновились.

Если `reconcile` уже ожидает выполнения или повторяется, новая версия заменяет его
цель и отзывает старый токен аренды. Повторный обход той же версии использует существующую
операцию и сохраняет задержку повтора. Частичный уникальный индекс БД не разрешает
две незавершённые операции для одного пользователя.

Перед эффектом исполнитель заново читает контракт и членство под блокировками.
Он применяет последнюю версию, даже если изменение произошло после постановки
операции. Успех сохраняет `applied_version`, `scheduled_version` и
`last_reconciled_at`; дата вступления, членство и расход приглашения не изменяются.
Тариф, абсолютный срок в обе стороны и внешний сквад назначаются существующим адаптером.

## Выход, истечение и сбои

Выход или исключение имеют приоритет над ожидающей сверкой. Под штатной блокировкой
пользователя старая операция отменяется и создаётся операция выхода с новым поколением
членства. Уже выполняющийся вызов Minishop завершается до принятия выхода, поскольку
удерживает ту же блокировку. Затем применяется стандартный триал либо отключение по
Q-02. Старый worker и последующие обходы не могут вернуть корпоративные условия
бывшему участнику, включая повторное вступление с новым идентификатором членства.

Истечение сохраняет группу, не выдаёт триал и не расходует приглашение. Просроченная
дата применяется как неактивный доступ. Продление возобновляет доступ нынешних
участников без нового кода. Пользователь по-прежнему может выйти для личной оплаты;
тексты API готовы, полный интерфейс относится к S09.

При неопределённом результате панели операция сохраняется в `retry` с ключом ошибки.
Повторы выполняет общая очередь S05; до подтверждения через Minishop успех не отмечается.
Личный платёж во время корпоративного членства не отменяется и не блокирует сверку.
Если пользователь включил автопродление либо появился неподдерживаемый C-01, адаптер
показывает соответствующий отказ и не отключает платёжные механизмы сам.

Сверка не запрещает самостоятельные покупки. Временное отклонение условий может
сохраняться до применения операции; при недоступности сервисов — дольше шести часов.
При выключенном плагине или worker сверка не выполняется.

## API состояния

Два набора маршрутов возвращают одинаковые структуры:

| Префикс | Доступ |
| --- | --- |
| `/api/admin/minishop-corp/contracts/<contract_id>` | Текущая глобальная роль администратора |
| `/api/plugins/minishop-corp/managed-contracts/<contract_id>` | Текущий управляющий именно этого контракта |

`GET <префикс>/synchronization` возвращает `{"ok": true, "synchronization": {...}}`:

| Поле | Значение |
| --- | --- |
| `contract_id`, `version` | Контракт и актуальная версия при чтении |
| `current_members`, `joining`, `departing` | Состав и незавершённые вступления/выходы |
| `confirmed` | Активные участники без ожидающей проверки или незавершённой операции, с подтверждённой текущей версией |
| `awaiting_dispatch` | Активные участники, которым ещё нужно поставить операцию новой версии или общего запуска |
| `pending`, `running`, `retrying` | Состояния операций активных участников |
| `last_checked_at` | Самая ранняя из последних успешных проверок активных участников; `null`, если проверок ещё нет хотя бы у одного из них |
| `next_sweep_at`, `sweep_running` | Единый срок следующего запуска и состояние обхода |
| `sweep_started_at`, `sweep_completed_at` | Начало текущего/последнего обхода и завершение последнего законченного обхода |

`confirmed` отражает последнее подтверждение через Minishop, а не непрерывное
наблюдение за подпиской. Последующий личный промокод станет виден при новой сверке.
Общие времена обхода не раскрывают участников или состояние чужих контрактов.

`GET <префикс>/synchronization/operations?limit=50&after=<uuid>` возвращает
`{"ok": true, "operations": [...]}`. Это незавершённые операции нынешних участников
данного контракта: поля [операции S05](membership-api.md), а также `user_id` и
`contract_version`. Лимит 1–100, порядок по UUID. Цель операции, секреты панели,
ссылки подписок и коды не выдаются. Каждый запрос заново проверяет сессию, блокировку
аккаунта и права; управляющий получает 404 для чужого контракта. `HEAD` ничего не меняет.

## Миграции и проверка

0003 добавляет отметки версий и успешного применения. Последующая 0004 убирает
индивидуальный срок, вводит общую строку расписания и `scheduled_run_id`.
Уже применённая при разработке 0003 сохранена неизменной; переход к общей задаче
оформлен следующей миграцией. Установленные данные членств сохраняются, начальный
обход проверяет их без ожидания старого индивидуального срока.

Проверки: [изменение условий и API](../tests/integration/test_reconciliation.py),
[обход, рестарт, конкуренция и обновление схемы](../tests/integration/test_sweeps.py).
Используются настоящие PostgreSQL, сервисы и DAL закреплённого Minishop. Только
внешнюю панель заменяет HTTP-сервер, который также позволяет задержать ответ во время
конкурирующего выхода/изменения контракта. Проверка установки подписанного пакета
дополнительно подтверждает запуск общей задачи штатным worker.
