# Сборка установочного пакета в GitHub Actions

Статус: реализовано и проверено локально. Ветка: `vibe/signed-artifact-ci`.

## Решение владельца от 9 октября 2026 года

GitHub Actions после push в любую ветку должен собирать подписанный плагин,
который можно скачать и загрузить в работающий Minishop. Проверки продукта
выполняются локально во время разработки. Actions не скачивает Minishop и
kiro-wheel, не устанавливает их зависимости и не запускает стенды или тесты.

Это изменение процесса S01/S10: прежний workflow воспроизводил локальную
приёмку и подписывал тестовый пакет временным ключом. Новая сборка использует
постоянный ключ издателя из GitHub Secret и сохраняет готовый результат как
артефакт запуска. Публикация в Git-ветку, Release и установка на бот в эту
задачу не входят. Бизнес-правила, миграции и заявленная совместимость неизменны.

Формат определяется [документацией пакетов Minishop](https://minishop.minidoc.cc/development/plugins/):
ZIP с `plugin.json`, SHA-256 payload-файлов, открытым ключом издателя и
Ed25519-подписью канонического manifest в `signatures/ed25519.sig`.
Генератор реализует этот формат; валидатор ядра вызывается только с локальным
флагом `--verify-host`. В Actions достаточно исходников плагина,
зависимостей сборки frontend и библиотеки подписи.

## Критерии приёмки

- Workflow запускается после push в любую ветку; сборка не требует checkout
  соседних проектов, Docker, PostgreSQL или зависимостей Minishop.
- Выполняются сборка frontend, упаковка, подпись и сохранение артефакта.
  Тесты, линтеры, проверки типов и интеграционные прогоны остаются локальными.
- Постоянный Ed25519-ключ поступает только в шаг подписи через Secret
  `MINISHOP_CORP_SIGNING_KEY` (base64 от 32 приватных байт). При отсутствующем
  или некорректном секрете сборка завершается понятной ошибкой; новый ключ
  автоматически не создаётся, секрет не выводится и не входит в пакет.
- Артефакт содержит установочный ZIP, `minishop-plugin.json`, открытый ключ
  и `SHA256SUMS`. В документации объяснено, какой ZIP загружать в Minishop,
  поскольку скачанный Actions artifact сам является внешним ZIP-контейнером.
- Автономная сборка локально воспроизводится без доступа к Minishop и
  kiro-wheel. Её результат принимается штатным локальным установщиком Minishop;
  постоянство ключа и воспроизводимость пакета сохраняются.
- README, правила разработки и инструкция установки соответствуют новому
  процессу. Все обязательные проверки перед коммитом выполняются локально.

## Результат

Workflow `Signed plugin package` собирает frontend, вызывает автономный генератор
с `--key-env MINISHOP_CORP_SIGNING_KEY` и сохраняет `dist/release/` в артефакт
`minishop-corp-<SHA commit>` на 30 дней. В summary выводятся путь установочного ZIP,
версия и хеш. Настройка ключа и порядок установки описаны в [инструкции](installation.md).

Локально выполнены:

- `scripts/check.sh`: Ruff, строгий mypy backend, 22 Python-теста, TypeScript,
  frontend build, 27 DOM-тестов, wheel и локали. Отдельно проверены типы сборочных
  модулей и сценария установки.
- Пять новых сценариев сборки: одинаковый постоянный ключ из файла и переменной
  даёт одинаковые байты; отсутствующий, пустой, некорректный и слишком короткий
  секрет отклоняются без его раскрытия или создания нового ключа.
- Чистая копия только исходников плагина, `npm ci --ignore-scripts`, сборка frontend
  и подпись в отдельном Python-окружении с тремя зависимостями `requirements-build.txt`,
  без исходников и Python-пакетов Minishop/kiro-wheel или инструментов тестирования.
  ZIP побайтово совпал с кандидатом S10: SHA-256
  `f1d218ee5d9cea9b833c4294f8651e142c6c3e42bcc01a19d1f68bead9b31962`.
- 212 интеграционных тестов, native smoke, 40 браузерных сценариев preview и
  8 сценариев полной оболочки Minishop с настоящими API.
- `scripts/package-check.sh`: чистая установка, доверие издателю, включение,
  выключение, обновление, повтор установки, удаление и восстановление с сохранением
  корпоративных данных и четырёх миграций.
- YAML, состав шагов и область передачи Secret; выполнение шага summary,
  shell syntax, локальные Markdown-ссылки и `git diff --check`.

Первые прогоны жизненного цикла выявили обрыв HTTP при штатном перезапуске backend
после сохранения операции. Локальный сценарий теперь не переиспользует соединения
между поколениями и при потере ответа проверяет точную операцию, новое поколение и
итоговое состояние через штатный `read_state`, затем ожидает оба launcher-процесса.
Ошибки HTTP не скрываются, повторная мутация вслепую не отправляется. После этой
правки полный прогон прошёл; код Minishop и рабочая логика плагина не изменялись.

Логи находятся в `.local/ci-package-*.log`; итоговый прогон установки —
`.local/ci-package-lifecycle-final.log`, данные его отдельного стенда —
`.local/package-check/1b90889bd74d4dcfbdb4bbc4d9366703/`. Стенды остановлены.
Соседние репозитории остались чистыми. Настройка секрета в GitHub, push,
удалённый запуск и установка на рабочий бот не выполнялись.
