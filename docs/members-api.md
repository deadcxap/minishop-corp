# Данные участников: S07

S07 реализует адаптер чтения и API списка участников и аватаров. Готовность этапа
отмечается в [плане](implementation-plan.md). Административный UI реализован в
[S08](admin-ui.md), пользовательский кабинет — в [S09](customer-ui.md).

## Источники статистики

`integration/member_data.py` получает существующий `SubscriptionService` Minishop.
Профили, наличие кеша аватаров и сохранённые показатели подписок читаются тремя
пакетными ORM-запросами для не более 100 разрешённых аккаунтов. Собственный адаптер
нужен потому, что штатный batch DAL не объединяет эти сведения и не включает
неактивные подписки. Записей в таблицы Minishop здесь нет.

Каноническая связь с панелью — поле `User.panel_user_uuid`. Если ему соответствует
несколько исторических подписок, адаптер не выбирает самую длинную в качестве текущей:
нужные сведения получает штатный сервис с кешем Minishop. При отсутствии однозначных
данных и недоступности сервиса значения остаются неизвестными.

Для трафика и разрешённого числа устройств используются готовые данные Minishop:
свежий кеш `_users_cache`, затем однозначная сохранённая подписка. Если значения
не хватает, вызывается `get_user_by_uuid`; сам Minishop читает свой кеш/Redis и
обновляет его штатным загрузчиком. Неполный или некорректный свежий кеш обновляется
через штатную инвалидацию. Лимит устройств из БД учитывает сохранённую базу,
дополнительные устройства и настройки по правилам административного списка ядра.

Количество устройств берётся из `_devices_cache` и `get_user_devices` Minishop.
При ошибке обновления доступен сохранённый `get_stale` в пределах срока, разрешённого
кешем ядра. Собственного кеша панели и прямого HTTP-клиента плагин не создаёт.
Один общий для экземпляра сервисов лимит допускает четыре параллельные загрузки,
в том числе при одновременных запросах нескольких страниц.

Статистика не вызывает `get_active_subscription_details`: этот метод может менять
срок подписки и отвязывать профиль при отсутствии в панели. Чтение корпоративной
таблицы не должно запускать такие изменения доступа.

## Показатели и профиль

Каждый из показателей `traffic_used_bytes`, `traffic_limit_bytes`, `device_count`,
`device_limit` имеет поля `value` и `state`:

| Состояние | Значение |
| --- | --- |
| `available` | Данные из действующего кеша или успешного штатного обновления |
| `stored` | Сохранённый показатель подписки; время последней загрузки ядром неизвестно |
| `stale` | Предыдущее значение из кеша Minishop после недоступного обновления |
| `unavailable` | Достоверного значения нет, `value` равен `null` |

Ноль использованного трафика или устройств означает полученный ноль; отсутствие данных
не заменяется нулём. Нулевой **лимит** означает безлимит по правилам Minishop.
Статистика относится к текущему периоду учёта ядра, а не к накоплению трафика с даты
вступления в организацию. Собственный корпоративный счётчик не создаётся.

Публичный профиль ограничен внутренним ID, именем, фамилией, username и Telegram-ссылкой.
Ссылка строится только при наличии привязанного положительного `telegram_id`:
`https://t.me/<username>` либо `tg://user?id=<telegram_id>`, если username отсутствует
или не подходит для безопасной ссылки. Внутренний ID не подставляется вместо Telegram ID.
Email, платёжные сведения, UUID панели, ссылки подписки, HWID и произвольные ответы
сервиса не возвращаются.

Проверки адаптера — [интеграционные тесты](../tests/integration/test_member_data.py).
Настоящие сервисы/DAL и кеш Minishop работают с PostgreSQL и HTTP-двойником панели.
Проверены попадание и промах кеша, обновление неполных данных, ошибки и старые значения,
неактивная подписка, неоднозначная история, отсутствие Telegram/профиля панели,
нулевые значения и 100 одновременных запросов при ограниченном параллелизме.

## HTTP API

Штатная сессия Minishop обязательна. Глобальный администратор использует префикс
`/api/admin/minishop-corp/contracts/{contract_id}`, назначенный управляющий —
`/api/plugins/minishop-corp/managed-contracts/{contract_id}`.

| Метод и суффикс | Ответ в конверте `{"ok": true, ...}` |
| --- | --- |
| `GET /members?limit=50&after=<UUID>` | `members` и `next_after` |
| `GET /members/{membership_id}/avatar` | `avatar` с изображением или состоянием отсутствия |

`limit` — от 1 до 100, по умолчанию 50; `after` необязателен. Пагинация идёт по UUID
членства без смещения. `next_after: null` завершает обход. Список содержит текущих
участников, включая ожидающих активации и выхода; бывших участников не возвращает.
Каждая строка содержит:

- `id`, `state`, `joined_at` — идентификатор и состояние членства;
- `profile` — разрешённые поля профиля, описанные выше;
- `statistics` — четыре показателя со своими состояниями;
- `avatar_path` — защищённый маршрут или `null`, если нет Telegram и кеша изображения;
- `operation` — последнее состояние операции S05/S06 без внутренних целевых данных.

Права управляющего ограничены своим контрактом; глобальная роль проверяется отдельно.
Чужой контракт, чужой или бывший участник дают `404`; заблокированный аккаунт и
недостаточная глобальная роль — `403`; отсутствие сессии — `401`. После ожидания
штатного обновления роль и членство проверяются повторно по БД. При выходе участника
во время загрузки он исключается из ответа; при отзыве роли весь ответ отклоняется.
Пагинация допускает изменения состава между запросами, поэтому отфильтрованная
страница может быть пустой с непустым `next_after` — UI должен продолжить обход.

Ответы имеют `Cache-Control: private, no-store`. `HEAD` проверяет права и читает
готовые сведения, не запускает обновление статистики или аватаров. Неизвестные
параметры отвергаются; у маршрута аватара параметров запроса нет.
Типы ответа для UI находятся в [members.ts](../frontend/shared/members.ts).

## Аватары

Маршрут аватара принимает UUID членства, а не произвольный ID пользователя. Сначала
проверяются контракт и действующее членство. Адаптер вызывает штатный помощник
Minishop для кеша Telegram: при отсутствии/устаревании изображения ядро получает его
через свой `Bot` и сохраняет через DAL. При отключённом Bot доступны сохранённые
изображения. Собственного кеша и загрузки по `telegram_photo_url` нет.

Пользовательский host API расширений работает с JSON, поэтому изображение возвращается
как `avatar.data_url`. Его нужно получать через `host.request`, затем назначать
источником изображения внутри UI плагина; токен сессии в URL не передаётся.
Допускаются только JPEG, PNG и WebP с соответствующими сигнатурами, размер исходного
изображения — не более штатных 512 КиБ. Произвольные URL и активные форматы вроде SVG
не возвращаются. `avatar.updated_at` содержит реальное время обновления кеша или `null`.

| `avatar.state` | Поведение UI |
| --- | --- |
| `available` | Показать изображение из актуального кеша |
| `stale` | Показать прежнее изображение с отметкой устаревания |
| `missing` | Нет Telegram и изображения в кеше; показать заглушку |
| `unavailable` | Изображение не получено или не прошло проверку; показать заглушку |

Штатный помощник одинаково возвращает отсутствие изображения при недоступности
Telegram и отсутствии фото. Поэтому без кеша используется `unavailable`, без
вымышленной причины; повторные загрузки ограничивает штатное охлаждение Minishop.
Обновление аватара может менять только штатный кеш изображений, но не подписку.

## Действия и проверки

Исключение, выпуск/отзыв и замена кода вызывают существующие операции
[членства](membership-api.md) и [приглашений](invitations.md).
Состояние массового применения условий доступно в [API сверки](reconciliation.md).
Новые маршруты чтения не обходят их авторизацию, CSRF, лимиты или очередь.

[Тесты API](../tests/integration/test_members_api.py) проверяют пагинацию, ожидающего
участника без профиля, разрешённые поля, чужие и бывшие членства, блокировку,
отзыв роли и смену управляющего. Отдельные конкурентные транзакции проверяют отзыв
прав и завершение выхода во время обновления статистики/аватара. Настоящий помощник
Minishop получает фото через локальный HTTP-двойник Telegram; проверены промах,
повторное использование кеша, отсутствие фото, недоступность сервиса, старое
изображение, недопустимые форматы/размер и отсутствие загрузок при `HEAD`.
