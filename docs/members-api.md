# Данные участников: S07

Первый блок S07 реализует адаптер чтения. Маршруты списка и аватара добавляются
следующим блоком этого этапа; готовность этапа отмечается в [плане](implementation-plan.md).

## Источники статистики

`integration/member_data.py` получает существующий `SubscriptionService` Minishop.
Профили, наличие кеша аватаров и сохранённые показатели подписок читаются тремя
пакетными ORM-запросами для не более 100 разрешённых аккаунтов. Собственный адаптер
нужен потому, что штатный batch DAL не объединяет эти сведения и не включает
неактивные подписки. Записей в таблицы Minishop здесь нет.

Каноническая связь с панелью — поле `User.panel_user_uuid`. Если ему соответствует
несколько исторических подписок, адаптер не выбирает самую длинную в качестве текущей:
нужные сведения получает штатный сервис с кешем Minishop. При отсутствии однозначных
данных и недоступности сервиса значения остаются неизвестными.

Для трафика и разрешённого числа устройств используются готовые данные Minishop:
свежий кеш `_users_cache`, затем однозначная сохранённая подписка. Если значения
не хватает, вызывается `get_user_by_uuid`; сам Minishop читает свой кеш/Redis и
обновляет его штатным загрузчиком. Неполный или некорректный свежий кеш обновляется
через штатную инвалидацию. Лимит устройств из БД учитывает сохранённую базу,
дополнительные устройства и настройки по правилам административного списка ядра.

Количество устройств берётся из `_devices_cache` и `get_user_devices` Minishop.
При ошибке обновления доступен сохранённый `get_stale` в пределах срока, разрешённого
кешем ядра. Собственного кеша панели и прямого HTTP-клиента плагин не создаёт.
Один общий для экземпляра сервисов лимит допускает четыре параллельные загрузки,
в том числе при одновременных запросах нескольких страниц.

Статистика не вызывает `get_active_subscription_details`: этот метод может менять
срок подписки и отвязывать профиль при отсутствии в панели. Чтение корпоративной
таблицы не должно запускать такие изменения доступа.

## Ответы адаптера

Каждый из показателей `traffic_used_bytes`, `traffic_limit_bytes`, `device_count`,
`device_limit` имеет поля `value` и `state`:

| Состояние | Значение |
| --- | --- |
| `available` | Данные из действующего кеша или успешного штатного обновления |
| `stored` | Сохранённый показатель подписки; время последней загрузки ядром неизвестно |
| `stale` | Предыдущее значение из кеша Minishop после недоступного обновления |
| `unavailable` | Достоверного значения нет, `value` равен `null` |

Ноль использованного трафика или устройств означает полученный ноль; отсутствие данных
не заменяется нулём. Нулевой **лимит** означает безлимит по правилам Minishop.
Статистика относится к текущему периоду учёта ядра, а не к накоплению трафика с даты
вступления в организацию. Собственный корпоративный счётчик не создаётся.

Публичный профиль ограничен внутренним ID, именем, фамилией, username и Telegram-ссылкой.
Ссылка строится только при наличии привязанного положительного `telegram_id`:
`https://t.me/<username>` либо `tg://user?id=<telegram_id>`, если username отсутствует
или не подходит для безопасной ссылки. Внутренний ID не подставляется вместо Telegram ID.
Email, платёжные сведения, UUID панели, ссылки подписки, HWID и произвольные ответы
сервиса не возвращаются.

Проверки адаптера — [интеграционные тесты](../tests/integration/test_member_data.py).
Настоящие сервисы/DAL и кеш Minishop работают с PostgreSQL и HTTP-двойником панели.
Проверены попадание и промах кеша, обновление неполных данных, ошибки и старые значения,
неактивная подписка, неоднозначная история, отсутствие Telegram/профиля панели,
нулевые значения и 100 одновременных запросов при ограниченном параллелизме.
