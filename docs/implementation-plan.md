# Текущее состояние

Версия исходников — **1.1.1**, локальная приёмка на Minishop **3.8.3, 3.8.4 и 3.8.5**
пройдена 13 ноября 2026. Пакет подготовлен локально; опубликована пока **1.1.0**.
Проверенная база — **Minishop 3.8.3** из
[dev/minishop.json](../dev/minishop.json). Поведение определено в
[требованиях](specification.md), покрытие — в [матрице приёмки](acceptance.md).
Дополнительная совместимость опубликованной **1.1.0 с Minishop 3.8.4** проверена
3 ноября 2026; изменения рабочего кода и новый выпуск плагина не потребовались.
Аудит **1.1.0 на Minishop 3.8.5** от 13 ноября выявил несовместимости новых
настроек рассылок: HTTP 500 списка групп пользователя и игнорирование исключений
из корпоративных аудиторий. В 1.1.1 реализована адаптация; результаты аудита
1.1.0 ниже сохранены как история, отдельно от приёмки исправлений.
[Подробности и воспроизведения](minishop-compatibility.md#проверка-minishop-385).

## Реализовано

- Контракты с тарифом Minishop, абсолютным сроком, необязательными сквадом и управляющим.
- Одноразовые и постоянные приглашения, лимиты, резервирование, смена, отзыв и удаление.
- Вступление по коду/ссылке, ручное добавление, выход и исключение с устойчивыми повторами.
- Применение условий через сервисы Minishop и общая сверка нынешних участников раз в 6 часов.
- Новый стандартный триал либо отключение доступа при выходе и исключении.
- Корпоративный триал без капчи Minishop 3.8.3, с сохранением защиты обычной выдачи.
  Совместимость вызова с 3.8.2 сохранена и проверена.
- Проверка отдельных автоплатежей Cryptomus/CISPay перед вступлением и выдачей доступа.
  Штатное расходование приветственного бонуса без дополнительных дней триала принято.
- Админка и кабинет управляющего: таблицы участников и приглашений, профили, статистика,
  управление ролью, диагностика и локализация RU/EN.
- Рассылки через штатный редактор Minishop: одна или несколько корпоративных подписок,
  неизменяемые наборы до 100 групп, доступ только администратору магазина.
- Группы пользователя и штатные исключения из аудиторий Minishop 3.8.5, включая
  счётчики и повторную проверку получателей перед доставкой. Прежние ядра используют
  прежний путь; нативные настройки и аудитории других плагинов сохраняются.
- Плитка настроек с типографикой установленного ядра на собственном DOM плагина.
- Штатное удаление аккаунта без блокировки корпоративными связями, включая выключенный плагин.
- Подписанный установочный пакет, Plugin API/host API 1 и одиннадцать миграций.

## Проверенная поставка

### Версия 1.1.1

На 3.8.3/3.8.4/3.8.5 прошли соответственно **378/392/417 PostgreSQL** проверок,
по **62 unit**, **59 DOM** и **55 Chromium** сценариев на каждом ядре. Ruff,
строгий mypy, TypeScript, сборки ESM/wheel и полнота RU/EN прошли на всех трёх.
На прежних ядрах пропущены только отсутствующие возможности: 39 и 25 сценариев.
Ожидаемых падений нет; строгая проверка плитки настроек сохранена.

Один подписанный ZIP 1.1.1 собран на базе 3.8.3 и прошёл установку, перезапуски,
повтор установки и переустановку на всех трёх ядрах. На 3.8.5 отдельно проверено
реальное обновление опубликованной 1.1.0: HTTP 500 списка групп исправлен,
контракты, приглашения, история и аудитории сохранены. Схема и одиннадцать миграций
плагина не менялись; постоянный ключ издателя сохранён. Все 61 файл runtime
совпадают с исходниками и собранным frontend.

Новые проверки охватывают штатные исключения и их отмену, независимый worker,
недоступные наборы, чужие провайдеры и повторную проверку перед настоящей доставкой
через HTTP-двойник Telegram. Исправлена также нестабильность подготовки тестовой
сверки; рабочий алгоритм сверки не менялся. Журналы — в `.local/release-1.1.1/`.
Закрепление 3.8.3 и lock-файл восстановлены без изменений; после исправления
тестового помощника на 3.8.3 и 3.8.5 прошли ещё по 43 проверки сверки.
Исходники всех трёх ядер чистые, стенды остановлены. Push не выполнялся.
[Подробности, хеш пакета и границы](minishop-compatibility.md#исправления-в-111).

### Публикация

Опубликованную версию определяет [индекс пакета](../minishop-plugin.json), а не номер
исходников. Actions публикует индекс и ZIP одним коммитом в основной ветке, затем
создаёт тег `v<версия>` на готовой поставке и GitHub Release. Другие ветки сохраняют
сборку в Artifacts. Порядок — в [инструкции](ci-packaging.md).

Сценарии публикации проверены на локальном Git и двойнике GitHub CLI: совпадение
тега и пакета, повторы после прерванных запросов, отказ при изменённых вложениях
и пропуск устаревшего запуска. Добавлены проверки задержки появления черновика
и вложений в GitHub API: ограниченное ожидание, сохранение черновика при таймауте
и продолжение без повторной загрузки. Workflow прошёл actionlint; сборка не требует Minishop.

Ранее пакет 1.0.1 был опубликован в индексе, тег `v1.0.1` указывает на коммит `ff37aa2`.
Первый запуск `publish` остановился после создания черновика из-за задержки GitHub API.
[Повторный запуск Actions](https://github.com/deadcxap/minishop-corp/actions/runs/38827097368)
завершился успешно: [Release 1.0.1](https://github.com/deadcxap/minishop-corp/releases/tag/v1.0.1)
опубликован с четырьмя вложениями, их хеши совпадают с файлами поставки.
Исправление ожидания проверено локально и не меняет содержимое пакета или его версию.

Версия **1.1.0 опубликована** 23 октября 2026: Actions создал коммит поставки
`1f81abc` и [Release 1.1.0](https://github.com/deadcxap/minishop-corp/releases/tag/v1.1.0).
SHA-256 опубликованного ZIP совпадает с проверенным локальным пакетом.

Первоначальный аудит 1.0.1 на Minishop 3.8.3 выявил шесть блокировок выхода
и исключения капчей. В 1.1.0 они исправлены; `xfail` заменены обязательными
проверками результата и сохранения обычной защиты. История аудита — в
[совместимости](minishop-compatibility.md#проверка-minishop-383).

## Ограничения и оставшиеся задачи

- Исключение использует платёжный параметр ядра только для пропуска капчи в одном
  корпоративном вызове; при обновлении Minishop его поведение нужно перепроверять.
- Действующие или будущие `FlexibleTrafficLimit` пока не поддерживаются.
- Локальные проверки не заменяют проверку конкретной рабочей панели, провайдеров
  входа/оплаты и Telegram-клиентов на выделенных аккаунтах.
