# Текущее состояние и план

Версия плагина — **0.1.6**. База — стабильный **Minishop 3.8.1** из
[dev/minishop.json](../dev/minishop.json). Поведение определено в
[требованиях](specification.md), проверки — в [матрице приёмки](acceptance.md).

## Реализовано

| Область | Состояние |
| --- | --- |
| Пакет и интеграция | Plugin API/host API 1, адаптер Minishop, девять миграций |
| Контракты | Тариф, абсолютный срок, необязательные сквад и управляющий, удаление пустой подписки |
| Приглашения | Одноразовые и постоянные коды, лимиты, резервы, повторный показ, отзыв, замена и удаление |
| Членство | Предпросмотр, подтверждение, выход, исключение и устойчивые повторы |
| Доступ | Применение условий через Minishop, новый триал или отключение при выходе |
| Фоновые операции | Очередь и общий шестичасовой обход нынешних участников |
| Управление | Админка, кабинет управляющего, профили, трафик, устройства и диагностика |
| Пользовательский UI | Вход из настроек, код/ссылка, членство и выход, RU/EN |
| Удаление аккаунта | Закрытие членства и отмена заданий средствами БД, в том числе без worker |
| Локальная проверка | PostgreSQL, сервисы Minishop, DOM/Chromium, установка и обновление подписанного пакета |

## Подготовка публичного репозитория

- Выполнено: документация о текущем поведении и требованиях без журналов разработки.
- Выполнено: воспроизводимое окружение без зависимости от других плагинов.
- В работе: сборка индекса и ZIP для установки по обычной ссылке на GitHub.

Критерий завершения: актуальные локальные ссылки и инструкции, успешные проверки
плагина и установки, проверка загрузки сгенерированного индекса штатным импортёром
Minishop, безопасная публикация одной версии и защита от устаревшего запуска Actions.

## Ограничения и оставшиеся задачи

- Действующие или будущие `FlexibleTrafficLimit` не поддерживаются; см.
  [совместимость](minishop-compatibility.md).
- Локальные интеграционные тесты используют HTTP-двойники панели и Telegram.
  Конкретная рабочая панель, провайдеры входа/оплаты и Telegram-клиенты требуют
  проверки на выделенных аккаунтах перед рабочим запуском.
- Настройка GitHub Secret и первый удалённый запуск сборки не подтверждены локальными
  проверками. Публикация репозитория и установка на рабочий бот остаются отдельными действиями.

Статус меняется на «выполнено» после соответствующих проверок. Незавершённые
и недоступные проверки указываются явно; история изменений хранится в Git.
