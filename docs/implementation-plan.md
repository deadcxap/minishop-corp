# Текущее состояние

Версия исходников — **1.1.0**.
Проверенная база — **Minishop 3.8.3** из
[dev/minishop.json](../dev/minishop.json). Поведение определено в
[требованиях](specification.md), покрытие — в [матрице приёмки](acceptance.md).

## Реализовано

- Контракты с тарифом Minishop, абсолютным сроком, необязательными сквадом и управляющим.
- Одноразовые и постоянные приглашения, лимиты, резервирование, смена, отзыв и удаление.
- Вступление по коду/ссылке, ручное добавление, выход и исключение с устойчивыми повторами.
- Применение условий через сервисы Minishop и общая сверка нынешних участников раз в 6 часов.
- Новый стандартный триал либо отключение доступа при выходе и исключении.
- Корпоративный триал без капчи Minishop 3.8.3, с сохранением защиты обычной выдачи.
  Совместимость вызова с 3.8.2 сохранена и проверена.
- Проверка отдельных автоплатежей Cryptomus/CISPay перед вступлением и выдачей доступа.
  Штатное расходование приветственного бонуса без дополнительных дней триала принято.
- Админка и кабинет управляющего: таблицы участников и приглашений, профили, статистика,
  управление ролью, диагностика и локализация RU/EN.
- Рассылки через штатный редактор Minishop: одна или несколько корпоративных подписок,
  неизменяемые наборы до 100 групп, доступ только администратору магазина.
- Штатное удаление аккаунта без блокировки корпоративными связями, включая выключенный плагин.
- Подписанный установочный пакет, Plugin API/host API 1 и одиннадцать миграций.

## Проверенная поставка

Функциональная приёмка 1.1.0 на Minishop 3.8.3: Ruff, строгий mypy, TypeScript,
сборка ESM и wheel, полнота RU/EN, **62 unit**, **59 DOM**, **377 PostgreSQL**
и **55 Chromium** сценариев (43 preview, 8 штатной оболочки и 4 рассылок).
Ожидаемых падений и пропусков на 3.8.3 нет. Все 22 проверки этой версии,
включая капчу, очистку аккаунтов и режим обслуживания, прошли.
Проверены выход и оба вида исключения с Redis и без него, повторы после сбоев
до/после активации с сохранением дат, стандартные лимиты и отсутствие платежей.
Обычная выдача триала для того же и другого аккаунта сохраняет требование капчи.
Дополнительно на Minishop 3.8.2 прошли **355 PostgreSQL** сценариев; 22 проверки
возможностей 3.8.3 пропущены. Старое ядро не получает отсутствующий параметр.

Проверены RU/EN, светлая и тёмная темы, мобильный и настольный экраны, клавиатура,
сенсорные кнопки, копирование и ручной вариант при запрете буфера обмена.
Галерея в [README](../README.md#скриншоты) использует синтетические данные.
Интеграционные проверки работают с настоящими сервисами/DAL Minishop, PostgreSQL
и HTTP-двойниками панели/Telegram. Рассылки в браузерных проверках создаются
отложенными и отменяются до отправки.

Подписанный ZIP 1.1.0 прошёл установку, синтетическое обновление, повтор установки,
выключение/включение, удаление/переустановку и сохранение данных. Проверены повтор
всех одиннадцати миграций, сохранность приглашений и аудиторий после перезапуска,
отказ рассылки при выключенном плагине и штатное удаление аккаунта.
Все 61 файл runtime совпадают с исходниками и собранным frontend; ключ издателя
сохранён. Журналы — в `.local/release-1.1.0/`, пакет и жизненный цикл — в
`.local/package-check/8d84c532930344618f1e444ffa941722/`. Контейнеры остановлены.
Схема и миграции плагина не менялись.

Опубликованную версию определяет [индекс пакета](../minishop-plugin.json), а не номер
исходников. Actions публикует индекс и ZIP одним коммитом в основной ветке, затем
создаёт тег `v<версия>` на готовой поставке и GitHub Release. Другие ветки сохраняют
сборку в Artifacts. Порядок — в [инструкции](ci-packaging.md).

Сценарии публикации проверены на локальном Git и двойнике GitHub CLI: совпадение
тега и пакета, повторы после прерванных запросов, отказ при изменённых вложениях
и пропуск устаревшего запуска. Добавлены проверки задержки появления черновика
и вложений в GitHub API: ограниченное ожидание, сохранение черновика при таймауте
и продолжение без повторной загрузки. Workflow прошёл actionlint; сборка не требует Minishop.

Пакет 1.0.1 опубликован в индексе, тег `v1.0.1` указывает на коммит `ff37aa2`.

## Ограничения и оставшиеся задачи

- Исключение использует платёжный параметр ядра только для пропуска капчи в одном
  корпоративном вызове; при обновлении Minishop его поведение нужно перепроверять.
- Действующие или будущие `FlexibleTrafficLimit` пока не поддерживаются.
- Локальные проверки не заменяют проверку конкретной рабочей панели, провайдеров
  входа/оплаты и Telegram-клиентов на выделенных аккаунтах.
