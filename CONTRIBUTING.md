# Разработка

Поведение продукта определяют [требования](docs/specification.md), готовность —
[текущее состояние](docs/implementation-plan.md). Краткие правила для агентов
находятся в [AGENTS.md](AGENTS.md).

## Окружение

Нужны Linux/WSL, Python 3.12, uv и Docker с Compose. Minishop 3.8.1 и образы
инструментов закреплены в [dev/minishop.json](dev/minishop.json).

```bash
bash scripts/fetch-minishop.sh
bash scripts/setup.sh
bash scripts/check.sh
bash scripts/integration-check.sh
```

Minishop загружается в `.local/minishop`. `MINISHOP_SOURCE` может указывать на другой
чистый checkout той же ревизии. `scripts/check-minishop.sh` проверяет его перед
настройкой, тестами и локальной упаковкой. Исходники ядра доступны только для чтения;
окружение, временные файлы, кеши и результаты находятся в этом репозитории.
Node и Chromium запускаются в закреплённых контейнерах. Подробности — в
[инструкции окружения](docs/development.md).

## Проверки перед коммитом

| Изменения | Обязательные проверки |
| --- | --- |
| Только Markdown | `git diff --check`, `git diff --cached --check`, локальные ссылки, формулировки и согласованность документов |
| Модель или доменная логика | Ruff, строгий mypy, целевые unit-тесты бизнес-правил |
| Миграции, лимиты, членство, повторы | PostgreSQL: конкуренция, повтор миграций и откат транзакций |
| API и права | Схемы, авторизация, штатный CSRF, чужой контракт и безопасные повторы |
| Адаптер Minishop | Контрактные и интеграционные тесты на закреплённой версии с HTTP-двойником панели |
| Фоновые задачи | Истечение, рестарт, два worker, выход и смена версии во время обработки |
| UI или локали | TypeScript, сборка, полнота RU/EN, DOM и браузер на мобильном/настольном экранах |
| Пакет, зависимости, CI | Полный доступный набор проверок, сборка и установка пакета на локальном стенде |

При изменении нескольких зон выполняйте соответствующие проверки.
Не пишите тесты, которые только повторяют простую обратимую правку.
Необязательное расширение прогона нужно лишь при новых рисках или неясной границе.
Если обязательная проверка недоступна, укажите причину и непроверенную область.

```bash
bash scripts/stand.sh up
bash scripts/stand.sh check
bash scripts/browser-check.sh
bash scripts/core-ui-check.sh
bash scripts/stand.sh down
bash scripts/package-check.sh
```

Последняя команда требует постоянного ключа издателя; подготовка описана в
[сборке пакета](docs/ci-packaging.md). Матрица требований и тестов — в
[проверках](docs/acceptance.md). Все тесты, линтеры и стенды выполняются локально.
GitHub Actions собирает подписанный пакет без окружения Minishop и публикует
индекс с ZIP в основной ветке; остальные ветки сохраняют результат в Artifacts.

## Архитектура

| Каталог | Ответственность |
| --- | --- |
| `backend/minishop_corp/` | Контракты, приглашения, членство, права, API и фоновые операции |
| `backend/minishop_corp/integration/` | Адаптер сервисов, DAL, авторизации и кешей Minishop |
| `backend/minishop_corp/storage/` | Собственная схема и транзакционные операции |
| `frontend/customer/`, `frontend/admin/` | Пользовательский и административный ESM-модули |
| `frontend/shared/`, `locales/` | Типы, компоненты и RU/EN |
| `tests/`, `dev/`, `scripts/` | Проверки, локальный стенд и сборка |

Minishop владеет подписками, профилями, тегами и сквадами. Все изменения проходят
через его сервисы/DAL; внутренние импорты сосредоточены в адаптере. Прямой клиент
Remnawave, запись таблиц ядра сырым SQL, глобальные подмены методов и фиктивные
платежи недопустимы. Не добавляйте платёжные, реферальные или уведомительные
побочные эффекты корпоративных переходов.

Храните даты как timezone-aware UTC. Метод прибавления дней не заменяет установку
точной даты. Новый триал использует штатный административный сценарий с сохранением
истории и всеми лимитами. Детали интеграции — в [совместимости](docs/minishop-compatibility.md).

Транзакция БД не делает вызов панели атомарным. Сохраняйте намерение, версию условий,
состояние и ключ повтора до вызова; неопределённый ответ проверяйте через Minishop.
Соблюдайте [порядок блокировок](docs/storage.md). Старое задание не должно вернуть
корпоративный доступ вышедшему участнику или затереть новые условия.

Таблицы используют `ext_minishop_corp_`, миграции — `minishop-corp.`. Миграции
append-only: применённые файлы не редактируются и не перенумеровываются.
Штатное удаление аккаунта завершает членство без триала средствами собственной
схемы, независимо от worker. Исторические записи не используются для авторизации.

## API и интерфейсы

Сохраняйте `{"ok": true, ...}` / `{"ok": false, "error": "..."}`. Проверяйте
сессию, бан, CSRF и доступ к конкретному контракту. Управляющий использует
пользовательское API; скрытая кнопка не заменяет серверную проверку.
Ссылка только заполняет код. Подтверждение повторно проверяет актуальные условия.

Python и исходный TypeScript типизированы. Широкие `Any`, `any`, `type: ignore`
и отключение проверки допустимы только с обоснованием конкретной границы интеграции.
Все видимые строки, aria-атрибуты и ошибки имеют ключи RU/EN.

UI использует host API, зарегистрированные страницы и слоты. Не импортируйте
внутренние компоненты ядра и не меняйте чужой DOM. Стили ограничиваются корнем
плагина; запросы, таймеры и обработчики очищаются при размонтировании.
Профили, трафик и устройства получайте через Minishop с ограничением параллелизма;
недоступные данные не превращайте в ноль.

## Коммиты и поставка

Рабочая ветка — `main`, если пользователь не указал другую. Каждый завершённый
связный блок оформляйте отдельным Conventional Commit на английском, например
`fix(invites): preserve activation limits on retries`. Не добавляйте `Co-Authored-By`
и не включайте посторонние изменения. Новое продуктовое поведение сначала опишите
в требованиях и критериях приёмки. Перед коммитом прочитайте diff и обновите статус.

Подписанный ZIP и индекс создаются генератором; собранные файлы, хеши и manifest
не правятся вручную. Постоянный ключ издателя, токены, реальные приглашения и данные
клиентов не входят в Git, логи или пакет. Смена проверенной версии Minishop требует
повторной приёмки; версия Remnawave не проверяется плагином.

Локальный коммит не означает push или установку на рабочий бот. В отчёте укажите
изменения, выполненные проверки, существенные ограничения и созданные коммиты.
